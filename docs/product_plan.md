# AI Market Brief MVP — Product Plan

> 產品：AI Market Brief MVP  
> 目標：30 日內完成零固定平台成本的可展示 Demo  
> 定位：每日跨資產市場簡報，不是即時終端、交易系統或個人化投資建議

## 1. 產品定位

AI Market Brief MVP 每日收集少量代表性市場數據、宏觀資訊及新聞，計算簡單市場特徵，再產生一份有資料時間、來源及風險提示的 AI 市場簡報。

第一階段只驗證一個核心假設：

> 用戶是否願意每日閱讀一份五分鐘內看完、有來源、涵蓋主要資產的 AI Market Brief？

產品不追求複製完整 Bloomberg。30 日 Demo 的價值是把分散資訊整理成清晰、可信、可每日重複使用的 Brief。

### 目標用戶

- 需要每日快速掌握市場狀態的個人投資者。
- 需要有來源市場摘要的財經內容創作者。
- 希望建立固定晨報／收市報流程的小型研究團隊。

### 核心價值

1. 一個頁面查看美股、BTC、黃金、外匯及宏觀狀態。
2. 用簡單指標指出市場有甚麼變化。
3. 用 AI 把已確認的數據及新聞整理成易讀 Brief。
4. 所有內容顯示資料時間、來源及延遲狀態。
5. 每日透過 Telegram 及 GitHub Pages 送達。

## 2. 30 日 Demo 範圍

### 固定資產清單

第一階段採用 8–12 個固定標的，不提供用戶自訂 Watchlist。

| 類別 | 建議 Demo 標的 | 用途 |
|---|---|---|
| 美股大盤 | SPY、QQQ | 股票市場方向與風險偏好 |
| 美股個股 | 3–5 隻大型科技股 | 展示個股市場變化 |
| BTC | BTC/USD | 加密資產風險偏好 |
| 黃金 | GLD 或單一黃金參考標的 | 避險資產代理 |
| 外匯 | EUR/USD、USD/JPY | 美元及主要外匯變化 |
| 宏觀 | 美國 10 年期利率及少量官方發布 | 市場背景 |

正式開發前鎖定清單；30 日內不增加新市場。

### 更新頻率

- 每日執行一次。
- 報告使用「最新可用快照」，不宣稱即時行情。
- 每筆市場數據顯示 `as_of`、來源及是否過期。
- 排程延遲不視為即時服務事故，但必須在報告中反映資料時間。

## 3. 第一階段功能

第一階段只包含六項能力。

### 3.1 Daily Scheduler

- 每日定時執行一次完整流程。
- 支援手動重跑。
- 同一天重跑時避免重複發布相同報告。

### 3.2 Market Data Adapter

- 從一個免費市場數據來源取得固定標的的日線或最新可用數據。
- 將供應商欄位轉換成統一格式。
- 來源失敗時顯示資料不可用，不在第一階段建立多供應商自動切換。

### 3.3 Macro / News Adapter

- 讀取少量官方宏觀來源、官方 RSS 或免費新聞 metadata。
- 保存標題、來源、發布時間及原文連結。
- 使用固定關鍵字及來源優先級，不建立複雜實體識別或重要性模型。

### 3.4 Feature Calculator

只計算四項可解釋特徵：

- 日變動。
- 週變動。
- 相對 SMA20 的趨勢。
- 20 日波動率。

所有數字由確定性計算產生，AI 不負責計算。

### 3.5 AI Brief Generator

只建立一個 `Daily Market Brief` 模板：

- 今日市場概況。
- 主要上升／下跌資產。
- 宏觀及新聞重點。
- 可能值得留意的風險。
- 明日／下一交易日觀察項目。
- 資料來源及免責聲明。

AI 只接收已整理的市場數字及附來源新聞。若 AI 服務不可用，系統使用固定模板產生基礎 Brief。

### 3.6 Telegram + GitHub Pages Publishing

- GitHub Pages 展示最新 Brief 及最近的有限歷史報告。
- Telegram 每日發送一次簡短摘要及 Dashboard 連結。
- 第一階段不發送盤中或事件驅動通知。

## 4. 第一階段明確不做

- 即時行情、盤中串流、Level 2 或 tick data。
- 事件驅動或高頻通知。
- 自動交易、券商連接或投資組合管理。
- 個人化買入／賣出建議。
- 用戶帳戶、自訂 Watchlist、付款或多租戶。
- 深度公司基本面研究及自動估值。
- 多條平行 AI 研究流程或複雜模型編排。
- 常駐 API server。
- 複雜持久化、佇列或資料處理基建。
- 多資料源自動 fallback、複雜新聞實體識別及全文搜尋。

## 5. 研究輸出標準

每份 Brief 必須包含：

1. `generated_at`：報告產生時間及時區。
2. `data_as_of`：市場數據截止時間。
3. `market_snapshot`：已確認的價格與特徵。
4. `key_headlines`：標題、來源、發布時間及原文連結。
5. `ai_summary`：清楚標示為 AI 整理的解讀。
6. `risks`：資料缺漏、過期及分析限制。
7. `sources`：本次使用的來源。
8. `disclaimer`：研究用途、非投資建議、資料可能延遲。

### AI 護欄

- AI 不取得或修改市場數字。
- AI 不可加入輸入資料中不存在的具體數字。
- 事實與推論分開表達。
- 沒有可信來源時，應明確寫「原因未確認」。
- 報告生成失敗時使用非 AI 模板，不阻塞發布。

## 6. 免費 Demo 驗收標準

### 產品驗收

- 一個公開連結可查看最新市場 Brief。
- Telegram 每日收到一則摘要。
- Brief 可在五分鐘內讀完。
- 每項市場數據有來源及 `as_of`。
- 每項新聞有來源、時間及原文連結。
- AI 不可用時仍能輸出基礎報告。

### 30 日技術驗收

| 指標 | Demo 目標 |
|---|---|
| 可展示版本 | Day 23 前完成 |
| 最終 burn-in | 最少連續 7 日 |
| 排程成功率 | burn-in 期間 ≥ 90% |
| 核心標的資料完整率 | ≥ 95% |
| 無來源的具體市場數字 | 0 |
| 固定平台成本 | US$0 |
| 每日報告數量 | 1 |

### 用戶驗證

- 邀請 5 名測試者。
- 至少 3 名願意在一週內閱讀 3 次。
- 記錄最有用、最不可信及可以刪除的內容。

## 7. 免費邊界

30 日 Demo 可使用：

- GitHub repository。
- 公開 repository 的 GitHub Actions。
- GitHub Pages。
- GitHub Secrets。
- Telegram Bot API。
- 免費或公開市場數據來源。
- 官方宏觀資料與 RSS。
- 靜態 JSON、Markdown 及 HTML。
- 免費 LLM 額度或用戶自備 API Key。

免費服務不代表有穩定 SLA。Demo 必須清楚披露數據可能延遲、缺漏或因免費來源改動而暫停。

## 8. Demo 後才評估

只有在用戶驗證通過後，才評估：

- 更可靠或更高頻的付費行情。
- 付費新聞及商業再分發授權。
- 自訂 Watchlist、登入及歷史搜尋。
- 常駐後端、managed database 及用戶資料。
- 更高用量 AI、更多研究模板及團隊功能。
- 商業化所需的法律、資料授權及合規工作。

## 9. 產品原則

1. **一份好 Brief 優先於大量功能。**
2. **每日批次優先於即時系統。**
3. **來源先於 AI 解讀。**
4. **單一可靠流程優先於多供應商抽象。**
5. **無 AI 仍可運行。**
6. **30 日內不增加第一階段範圍。**
